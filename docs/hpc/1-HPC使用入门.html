〇、开始之前：写给没碰过 Linux 的你（10 分钟热身）

本指南后面的操作大量发生在“黑窗口里敲命令”。若你此前只用 Windows 双击软件、从未接触过 Linux，请先读完本节——只需建立 3 个画面、混个脸熟几个词，后面每章的操作就都能看懂了。

0.1 画面一：集群是一间“餐厅”（登录节点＝大厅，计算节点＝厨房）

SZBL HPC 集群不是一台电脑，而是几十台服务器协同工作的整体。先理解三个角色：

角色是什么对你的意义
登录节点（大厅）用 Xshell/终端连上后所在的地方只能在这里做“准备工作”：传文件、建目录、写脚本、敲命令提交任务——它本身不跑真正的分析，也不要在上面直接跑 DIA-NN
计算节点（厨房）几十台真正干活的服务器分析实际运行的地方；不能直接进入，必须先通过 Slurm 调度器申请到一台（salloc 或 sbatch，见下）
共享存储（公用冰箱）登录节点与计算节点看到的是同一份文件在登录节点上传的 .raw，作业在计算节点直接能读；集群上文件地址形如 /lustre/账号名/…

“向调度器申请计算节点”有两种方式，后面每章都会用到，务必分清：

方式类比特点
salloc（交互式）餐厅“包间现做”申请到节点后你登录进去现场操作、盯着输出；人必须守着，用完手动“退房”（两次 exit），否则一直计费——只适合短调试
sbatch（批处理）“点外卖”把命令写进 .sh 脚本交给调度器，它排队→自动运行→结束自动停止计费；期间断网、关机都不影响——正式分析一律用这个

0.2 画面二：一切操作靠“敲命令”，没有按钮

集群上所有操作＝输入一行文字、按回车。每行格式固定：程序名 参数1 参数2 …（参数告诉程序做什么、对谁做）。参数你看不懂没关系——本指南每条命令都可以整行直接复制：Xshell 中默认单击右键即粘贴（MobaXterm 用 Shift+Insert），再按回车执行。屏幕行首的 $ 等符号叫“提示符”，只表示“终端就绪、等你输入命令”，复制时不要把它带进去。

命令执行后没有报错通常就是成功；报错了也别慌——把红字整段截图，先到本册第四章 FAQ 里找，或问组里跑过的人。出现频率最高的几个命令与 Windows 习惯对照如下：

集群命令作用（Windows 类比）
ls / ls -l查看当前文件夹内容（-l 附加大小的详情列表）
cd 目录名进入某个文件夹
pwd显示“我现在在哪个目录”（完整路径）
mkdir 名字新建文件夹（右键新建文件夹）
cp / mv / rm 文件复制 / 移动（也可当重命名）/ 删除——rm 没有回收站，删前务必想清楚
cat 文件把文件内容打印到屏幕（≈记事本打开看）
vim 文件编辑文件（本册 3.4 步骤 1 括号里有 vim 三步速记；更详细教学见分册 2《DIA-NN 数据分析》4.1“新手实操”框）

0.3 画面三：文件有“路径”，如同快递地址

目录＝文件夹；路径＝从“根”出发的完整地址，形如 /lustre/你的账号名/raw（开头的 / 表示根，各层目录用 / 分隔）。每次登录后默认落在自己的家目录，用 ~ 表示（≈Windows 的“我的文档”，通常就是 /lustre/账号名）。命令里只写文件名（如 diann_job.sh）＝指“当前目录下的这个文件”；先 pwd 可确认当前目录，cd /完整/路径 可跳到任意目录。文件传输工具里看到的 /lustre/账号名/xxx 就是集群上的文件位置。

关键词一句话解释先在哪遇到

0.5 补一张全景图：Slurm 管机器，Singularity 管软件

常有新手问：命令里出现的 salloc 和 singularity 到底什么关系？为什么指南与脚本里会写“Slurm + Singularity 的镜像容器”？这一节把两套系统一次分清——以后看到任何一条集群命令，都可以先归位：它是在“要机器”，还是在“跑软件”。

用分册 3 里 FragPipe 的启动命令做逐行拆解（其他分析同理）：

命令属于哪套系统在干什么
salloc -N 1 -n 32Slurm（调度器）向集群排队申请一台 32 核计算节点（salloc＝交互式申请、sbatch＝批处理提交、squeue＝看状态、scancel＝释放，均属“要机器”，见 0.1 与第三章）
ssh -Y cuXXX接续 Slurm登进刚分给你的那台计算节点（-Y 开启 X11 图形转发，窗口类程序必需）
module load singularity/ce-3.8.0Singularity（容器引擎）加载容器工具——“跑软件”的第一步
singularity exec … fragpipe-24.0-local.sif … /bin/fragpipeSingularity以“容器”方式运行镜像里的软件；.sif 就是平台预制的软件打包文件，容器内的路径整段照抄即可

为什么要这样组合？两条原因一次说透：① 为什么必须 Slurm——集群是共享资源，所有重计算都要经计算节点排队运行、按核时计费（登录节点只做准备工作），Slurm 就是那个“发号 + 计时”的调度器；② 为什么用 Singularity 镜像——软件（DIA-NN / FragPipe）连同依赖被平台预先打包成 .sif 镜像，你不需要安装任何东西，用时“借集装箱”运行；平台不支持 Docker，HPC 场景统一用 Singularity。

“Slurm + Singularity 的镜像容器”——这句话到底在说什么？ 它不是另一种运行方式，而是对上面整套运行环境的简称：机器由 Slurm 发放（salloc / sbatch），软件在 Singularity 镜像里运行——你刚看过的命令就是它的全部。分册 3 配套脚本 fragpipe_gui.sh 开头标注的“适用环境：SZBL HPC 一号集群（Slurm + Singularity；FragPipe 24.0 容器镜像）”就是这个意思（脚本内部依赖 squeue / scancel 与 singularity，换到没有这两套系统的环境就跑不了）；脚本与手动命令的关系也很简单：启动命令一字不差，只是外加了自检与自动收尾。启动命令里的 --bind / --env 可理解为给容器“接线”（把图形授权、语言环境接进容器里），照抄即可，无需深究。
阅读路线建议（分册版） 第一次上手请按 ① 通读本册 〇 → 一 → 二 → 三 打基础；随后按需进入专册：用 DIA-NN 做定量分析读 分册 2（4.0-4.4），用 FragPipe 图形界面读 分册 3（5.0-5.4，其中 5.0/5.1 会再次用到本册三章的 salloc 与 X11 概念）。本册第四、五章（FAQ 与资源）随时回查。每章卡住时回到本节找名词解释。

1.3 登录一号集群（两种常用方式）

先认识一个词：堡垒机＝集群的“门卫/跳板”。集群内部机器不直接对外网开放，所有连接必须先经堡垒机验证身份再转进内部（类比：先出示工牌进大楼，再刷卡进实验室）。下面两种方式任选其一走通一次，之后日常都走第 2 种（复制粘贴方便）。

方式方法适用场景
Web 堡垒机（行云管家）浏览器访问 http://10.68.247.110/login.html → 团队 → 主机 → 快速访问（Web 桌面），输入账号密码；建议“存为快捷方式”配置、偶尔使用、忘记命令时（Web 端复制粘贴不便，不适合日常敲命令）

1.4 文件传输

推荐 FileZilla / WinSCP：协议 SFTP，主机 10.68.247.101，端口 22，使用邮件中的集群账号密码登录。原始谱图（.raw/.mzML）、fasta、谱库等大文件一律先上传到集群再提交作业，切勿在本地直接分析大批 DIA 数据。

第一次用 FileZilla（界面速成） 打开后顶部依次填：主机 10.68.247.101、端口 22、用户名与密码＝集群账号密码（注意：不是堡垒机串密码），点“快速连接”。成功后窗口分两栏：左＝本地电脑文件，右＝集群文件；把文件从左边拖到右边即上传（从右拖到左即下载），传整个文件夹直接拖文件夹。传输期间勿关窗口，完成后在右侧核对文件大小无误。SFTP 本质＝带加密的文件传输协议，使用体验与 Windows 资源管理器无异。

1.5 会话保活与长任务

网络波动导致终端断开时，正在敲的命令、正在跑的调试都会中断。把会话放进 tmux（一个“虚拟终端容器”，让进程挂在后台、不随断线消失）再操作即可避免。tmux 基本用法：tmux 新建会话并进入；中途要离开时按 Ctrl+B 松开后，再按 D 脱离（界面消失但里面程序继续跑）；重新连上集群后 tmux attach 恢复现场；彻底结束时在 tmux 界面里输入 exit 关闭该会话。

团队经验真正“跑大作业”不要依赖交互终端，统一用本册 3.4 的 sbatch 批处理：提交后即使本机关机、断网也不影响运行，这是最稳妥的方式（DIA-NN 正式分析模板见分册 2）。

费用与数据安全要点 ① 只有“作业在运行”才产生机时费——上传/下载文件、打开网页服务本身不收费；但占着节点不释放 = 持续计费（见本册 3.3）。 ② 内部课题组用单位经费结算时另有 5～6 折优惠（具体以平台结算为准）；若课题组年度机时＋存储消费不足 2000 元，次年 1 月可能加收 2000 元/年账户管理维护费——按需正常使用一般可避免。 ③ 集群不做用户数据备份，重要原始数据请自行多副本保存（本地盘 + 归档存储）。

三、Slurm 作业基础（必须掌握）

第 0 章讲过：真正计算要先向 Slurm 调度器申请。本章给你一套能立刻上手的命令链：查看资源 → 申请节点 → 提交作业 → 查状态/取消，配合 0.2 的命令对照表阅读。本章是《DIA-NN 数据分析》（分册 2）与《FragPipe 数据分析》（分册 3）两册的公共基础，请勿跳过。

3.1 核心概念

partition/队列同硬件配置的节点集合，如 cu-1、cpuPartition（用 sinfo.sh 输出第一列查看，不要把具体节点名如 cu029 当队列写进脚本）。

作业状态PD/PENDING 排队 · R/RUNNING 运行 · C/COMPLETED 完成 · FAIL 失败 · S/SUSPEND 挂起 · REQUEUED 重排队。用 squeue -l 查看（第一列 JOBID 是作业号）。

3.2 查看集群资源

# 队列资源总览（partition / 空闲 / 已分配 / 节点列表）
sinfo.sh        或 sinfo
# 逐节点状态：状态 / 已用/空闲核数 / 负载 / GPU 分配等
pestat          # 找 cpuPartition、cu-1 等队列看哪些节点空闲、每节点核数

3.3 交互式申请节点（调试、GUI 程序用）

# 申请 1 个节点、32 核；-p 指定队列（不写默认 cu-1）
salloc -p cu-debug -N 1 -n 32
# 分配成功后会显示：Granted job allocation 作业号 → 再 ssh 登录到计算节点
ssh cuXXX        # cuXXX 换成上面分配到的节点名（如 cu073）；成功标志：提示符变为 账号@cuXXX
hostname         # 想确认自己此刻在哪个节点，敲 hostname 即显示节点名
高危：交互式作业用完必须释放！ 交互式（salloc）占用的资源在您退出登录后仍在后台计费，务必执行 两次 exit（先退出计算节点、再退出申请会话，释放 salloc 作业），或用 squeue -l 找到作业号后 scancel JOBID 释放。 团队实际教训：曾因 salloc 后长期未释放，单笔产生 20 余元费用。运行中的计算不会自动停止计费！

3.4 批处理提交（sbatch，日常推荐）

1
在数据目录新建脚本（vim 编辑：vim job.sh，按 i 进入编辑，Esc 退出编辑，输入 :wq 保存退出）。
2
按需填写头部 #SBATCH 资源申请（作业名 / 队列 / 节点数 / 每节点核数 / 时限 / 输出文件）。小知识：以 # 开头的行是“注释”——#SBATCH 行是给调度器看的点菜单（作业怎么跑），其余 # 行是给人看的说明，都不参与计算；修改模板时只动 #SBATCH 行与末尾的实际命令即可。
3
提交：sbatch job.sh → 返回 “Submitted batch job 作业号”；查看 squeue -l；取消 scancel 作业号。
#!/bin/bash
#SBATCH --job-name=demo          # 作业名
#SBATCH --partition=cu-1         # 队列（32核节点；测试可换 cu-debug）
#SBATCH --nodes=1                # 节点数
#SBATCH --ntasks-per-node=32     # 每节点申请核数（计费依据；DIA-NN 用 --threads 配套，见分册 2 的 4.4③）
#SBATCH --time=24:00:00          # 运行时限（超时会被杀死，按任务估足）
#SBATCH --output=%j.out          # 标准输出（%j = 作业号，自动命名）
#SBATCH --error=%j.err           # 错误输出
# 下面放你的实际命令（DIA-NN / FragPipe 后台版 / 其他软件）
echo "job start: $(date)"
常用命令作用
squeue -l查看排队/运行作业（TIME 已运行、TIME_LIMI 时限、NODELIST 所在节点）
scancel JOBID取消作业（可 scancel 数组号_[1-5] 批量取消）
sacct历史作业与状态
scontrol show job JOBID --detail作业详情（节点、CPU/GPU 分配）
tail -f 作业号.out实时查看运行日志（排错利器）
团队经验总结 ① 能 sbatch 就不要 salloc：批处理作业命令跑完自动结束、自动停止计费，无需人守着；交互作业易忘记释放而产生额外费用。 ② 线程数：cu-1 是 32 物理核（超线程共 64 逻辑核），申请 64 核、跑 64 线程可以正常排队运行（组内实测；早期“不允许/更慢”的旧经验作废，详见分册 2《DIA-NN 数据分析》的 4.4③）——但超线程对 DIA-NN 这类计算密集流程通常没有额外加速，想提速优先用 ③ 的并行拆分。 ③ 同一批样本可分多个作业并行提交（如 9 个 raw 拆成 3 个作业 ×3 文件），往往比单作业更快上机。 ④ 作业排队久？sinfo.sh 看看是否有其他课题组集中投递；可等待或换空闲队列。

四、常见问题（FAQ）

以下为集群通用问题（登录/计费/作业等）；DIA-NN 软件本身的常见问题见分册 2 的 4.4，FragPipe 相关见分册 3。

问题解答
为什么 Xshell 连不上 ln01？2 号集群却能连一号集群只允许经堡垒机跳转（Web 或“串名串密码”方式，端口 8022），不允许直连；二号集群才允许直连。手册中 “SSH 登录 = Yes” 均指经堡垒机。
sbatch 提交后 squeue -l 看不到作业大概率脚本里 #SBATCH --partition 写错：队列名是 sinfo.sh 输出的第一列（cu-1、cpuPartition 等），不是节点名（cu029）。可先 bash -n 脚本 检查语法。
账单费用和实际对不上 / 想查具体作业费用费用每周一、周四更新，非实时；界面显示的“截至时间”为计费系统更新点而非作业结束时间。命令行 sbill（仅一号集群）可查当月/指定月明细：sbill --time 202602 --long（个人）或 sbill -g（课题组，仅见自己作业明细）。
为什么产生几十元的“意外”费用多为 salloc 交互作业未释放：作业早已不用但一直挂着计费。用 squeue -l 找到后 scancel JOBID；以后长任务改用 sbatch。
登录节点上 wget/curl 下载报 403先执行 source /lustre/software/proxy/set_proxy.sh 再下载；仍失败联系管理员（可能需加白名单）。
交互式 salloc 后 ssh 计算节点总是断/没反应确认登录的是分配到的节点名；网络抖动时优先用 tmux 保活。salloc 会话如果断线，作业仍可能占着资源，重连后及时 squeue 检查并清理。
想本地画图（R/ggplot 等）图形不显示本地起 X server + SSH 开启 X11 转发，连计算节点用 ssh -Y；测试命令 xclock（FragPipe 图形界面也是同一机制，见分册 3 的 5.0/5.1）。
我的 conda/R 环境加载很慢主存储为并行文件系统，小文件多时慢属正常。建议把 conda 环境装到全闪快速存储（联系平台开通 /flashfs1/work 配额），大 IO 作业临时文件放 /flashfs1/scratch.global，跑完拷回家目录。
作业跑很久都没结束，怎么看状态？squeue -l 看 TIME；ssh 计算节点 后 top -u 账号 看进程/CPU；结合 tail -f 作业号.out 判断是在正常计算还是卡死。作业超过时限会被系统终止，请按需估足 --time。
能否在集群上用 Docker？不能，平台仅支持 Singularity 容器；DIA-NN/FragPipe 均以 sif 镜像方式提供。
重要数据怕丢怎么办平台不对用户数据做备份。请自行备份：原始数据与关键结果在本地盘/移动硬盘各存一份，温冷大文件可迁移到归档存储 /nasfs1（按量计费 0.4 元/TB·天）。
