SSH 登录服务器 → 申请 GPU 计算资源 → 激活 Python 环境 → 配置网络代理 → 启动 QoderCN。

这里有个关键点：HPC 通常分为登录节点和计算节点。你先通过 SSH 进入登录节点，再用 `srun` 申请计算资源，之后才在获得的计算环境里运行后续命令。

## 一、完整命令流程

第 1 步：SSH 登录 HPC

```
ssh uu1s5v865@10.68.247.110 -p 8022
```
这个IP地址也是深圳湾实验室提供的，节点名称叫行云堡垒机，1，2号集群共用，相比于别的节点，这个可以在终端直接用ssh登陆远程连接，如果想用ssh登陆，最好用这个节点。
输入实验室提供的密码。输入密码时，终端通常不会显示字符或星号，这是正常现象。

第 2 步：申请计算资源

```
srun -p cu-1 -N 1 -n 1 --pty /bin/bash
```

向调度系统申请一个节点、一个任务，并启动交互式 Bash Shell。

第 3 步：激活软件环境

```
micromamba activate bac_env
```

切换到名为 bac_env 的环境，使用其中安装的 Python 和相关依赖。

第 4 步：加载代理配置

```
source /lustre/software/proxy/set_proxy.sh
```

在当前 Shell 中加载实验室提供的代理环境配置，帮助需要通过代理访问外网的程序连接网络。

第 5 步：启动 QoderCN

```
qodercn
```

启动名为 qodercn 的命令行程序。它是否能正常启动，取决于程序已安装、命令在 PATH 中，以及相关运行环境和网络配置正常。

## 二、逐条解释：为什么要这样输入？

### 1. SSH 命令：进入实验室 HPC

```
ssh uu1s5v865@10.68.247.110 -p 8022
```

| 参数              | 含义       | 为什么需要                                 |
| --------------- | -------- | ------------------------------------- |
| `ssh`           | 安全远程登录工具 | 从本地电脑连接远程 Linux 服务器                   |
| `uu1s5v865`     | 用户名      | 告诉服务器以哪个账号登录                          |
| `@`             | 分隔符      | 分开用户名和服务器地址                           |
| `10.68.247.110` | 服务器 IP   | 指定要连接的服务器                             |
| `-p 8022`       | SSH 端口   | 指定服务器的 SSH 服务监听在 8022 端口，而不是默认的 22 端口 |

`-p` 是 SSH 的端口参数。这里的 IP 和端口是你提供的实验室连接信息，我无法仅凭命令确认该 IP 对应的具体服务器角色。

Linux man page



为什么要输入密码？

SSH 需要验证你的身份。连接后，如果服务器要求密码，就输入实验室为该账号设置的密码。

注意：

- 密码输入时通常没有任何字符显示，直接输入后按 Enter 即可。
- 不要把密码写在 SSH 命令中，也不要发到聊天记录或公开文档里。
- 如果出现 `Permission denied`，可能是账号、密码或认证方式有问题；如果出现 `Connection timed out`，则需要检查网络、VPN 或服务器连通性。

### 2. `srun` 命令：为什么 SSH 之后还要再执行一次？

```
srun -p cu-1 -N 1 -n 1 --pty /bin/bash
```

这是整个流程里非常重要的一步。

SSH 登录成功，不等于你已经获得计算节点或 GPU 资源。 SSH 通常只是让你进入 HPC 的登录环境；`srun` 则通过 Slurm 调度系统申请资源，并启动一个交互式终端。


| 参数          | 含义                |
| ----------- | ----------------- |
| `srun`      | 向 Slurm 提交运行任务    |
| `-p cu-1`   | 指定使用名为 `cu-1` 的分区 |
| `-N 1`      | 请求 1 个计算节点        |
| `-n 1`      | 请求 1 个任务（task）    |
| `--pty`     | 为任务连接交互式伪终端       |
| `/bin/bash` | 启动 Bash 命令行 Shell |

为什么这么设置？

- `cu-1`：按你提供的实验室命令选择对应分区。分区名称本身不能证明它一定是 GPU 分区，具体要以实验室的 HPC 配置为准。
- `-N 1 -n 1`：适合先申请一个节点、运行一个任务的简单交互式操作。
- `--pty /bin/bash`：让你进入可交互的命令行，而不是执行完某个命令就退出。

一个容易误解的地方： `-N 1 -n 1` 并不代表申请了一张 GPU，也不代表获得了整台服务器的全部资源。它只描述节点数和任务数。若 QoderCN 的使用流程需要 GPU，是否需要额外指定 GPU 参数，应以实验室的资源配置和使用要求为准。

执行后，你可能会看到类似：

```
srun: job 123456 queued and waiting for resources
srun: job 123456 has been allocated resources
```

这是示例输出，不是你实际的作业编号。第一行表示等待资源，第二行表示资源已经分配。此时终端提示符可能会改变，表示你进入了分配到的计算环境。

### 3. `micromamba activate bac_env`：为什么要激活环境？

```
micromamba activate bac_env
```

这条命令用于激活名为 `bac_env` 的软件环境。

可以把环境理解成一个独立的软件工具箱，里面可能有指定版本的 Python、依赖包和其他程序。

- `micromamba`：轻量级的 Conda 兼容环境与包管理工具。
- `activate`：激活某个环境，让当前 Shell 使用该环境对应的程序和配置。
- `bac_env`：环境名称，需要在服务器上事先创建好。

为什么不能直接运行？

如果不激活正确环境，可能会出现：

- Python 版本不对。
- 找不到需要的依赖包。
- 调用到了其他环境中的程序。
- 环境变量或 PATH 不符合预期。

你可以用下面的命令检查环境是否生效：

```
micromamba env list
which python
python --version
```

其中 `which python` 可以帮助你确认当前调用的是哪个 Python。

如果提示环境不存在，先检查环境名称；如果提示 `micromamba activate` 无法执行，可能需要按实验室的配置初始化 Shell。

### 4. `source` 命令：为什么要加载代理？

```
source /lustre/software/proxy/set_proxy.sh
```

这条命令用于在当前 Shell 中执行指定的脚本。

- `source`：读取并执行脚本，让脚本设置的环境变量等配置留在当前 Shell 中。
- `/lustre/software/proxy/set_proxy.sh`：实验室提供的代理配置脚本路径。
- `set_proxy.sh`：从文件名看，它用于设置代理相关配置；具体设置内容需要查看脚本才能确认。

为什么可能需要代理？

HPC 计算节点经常会对外网访问进行限制。如果 QoderCN 需要访问外部服务，代理可能帮助它建立网络连接，例如访问服务端点或下载所需资源。

需要注意：加载代理不等于一定能访问外网。 是否能访问取决于脚本配置、代理服务状态、网络策略以及目标服务本身。

可以用以下命令检查代理环境变量：

```
env | grep -i proxy
```

如果没有任何输出，不一定说明脚本失败，也可能是脚本使用了其他配置方式；要确认实际行为，需要查看脚本内容。

### 5. `qodercn`：为什么最后执行它？

```
qodercn
```

这条命令用于启动 QoderCN。

它被放在最后，是因为前面的步骤分别准备了：

1. 远程登录权限。
2. 计算节点的交互式运行环境。
3. 所需的软件依赖。
4. 可能需要的网络代理。

不过，`qodercn` 的确切行为取决于你安装的版本和实验室的配置。我不能仅凭这个命令名确定它会打开什么界面、连接哪个服务，或是否需要额外参数。

可以先检查它是否存在：

```
which qodercn
```

如果没有输出，可能是程序没有安装，或者它的安装目录没有加入当前环境的 `PATH`。

## 三、为什么顺序不能随便换？

| 顺序 | 命令                            | 核心目的      |
| -- | ----------------------------- | --------- |
| 1  | `ssh ...`                     | 进入 HPC    |
| 2  | `srun ...`                    | 获取交互式计算资源 |
| 3  | `micromamba activate bac_env` | 准备软件环境    |
| 4  | `source .../set_proxy.sh`     | 准备代理配置    |
| 5  | `qodercn`                     | 启动程序      |

这里有两个特别重要的细节：

- 环境激活和代理配置应在准备运行 QoderCN 的那个 Shell 中执行。 如果你退出了该 Shell，再重新进入计算环境，就应该重新检查这些设置。
- `srun` 结束后，分配的资源通常会释放。 当你输入 `exit` 退出交互式 Shell 时，不应假设之前的计算资源还会继续保留。

## 四、最方便的日常使用版

如果实验室已经配置好所有依赖，你可以每次按下面的顺序操作：

第一步：在本地电脑的终端执行 SSH

```
ssh uu1s5v865@10.68.247.110 -p 8022
```

第二步：登录成功后，在远程终端执行

```
srun -p cu-1 -N 1 -n 1 --pty /bin/bash
```

第三步：进入交互式计算环境后依次执行

```
micromamba activate bac_env
source /lustre/software/proxy/set_proxy.sh
qodercn
```
